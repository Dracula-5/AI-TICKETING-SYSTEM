# Datasets

Every dataset used for training or evaluation, with provenance, license and preparation.
Raw files are pinned by SHA-256 in `ml/nexadesk_ml/datasets.py` (`MANIFEST`); preparation is
`python -m nexadesk_ml.datasets all`. Raw and processed data are not committed.

## Data-origin labels

| Label | Meaning | Where it appears |
|---|---|---|
| **PUBLIC — real** | Real-world records released publicly | UCI incident log, CQADupStack |
| **PUBLIC — synthetic** | Publicly released, but generated (not real tickets) | Support-ticket texts |
| **SYNTHETIC (ours)** | Generated by `nexadesk_ml/synthetic.py` from explicit parameters | `data/synthetic/` |
| **DEMO** | Hand-written illustrative tickets seeded into demo orgs | `backend/app/scripts/seed_demo.py` |
| **REAL USER** | Genuine usage of a deployment | none yet |

In the application database the same distinction is the `data_origin` column (`real`, `demo`,
`synthetic`) on organizations, users and tickets. Metrics are never mixed across labels.

## 1. UCI — Incident management process enriched event log

| | |
|---|---|
| Label | **PUBLIC — real** (anonymized ServiceNow audit log of an IT company) |
| Source | UCI Machine Learning Repository, dataset 498 |
| URL | https://archive.ics.uci.edu/dataset/498 |
| Citation | Amaral, C., Fantinato, M., Peres, S. (2018). doi:10.24432/C57S4H |
| License | CC BY 4.0 |
| Raw size | 141,712 events, 36 attributes |
| Prepared | 24,918 incidents (one row each), opened 2016-02-29 → 2017-02-16 |
| Used for | P4.2 routing, P4.4 SLA-breach prediction, P4.5 resolution time; resolution-time distributions for the synthetic generator |

**Preparation (`prepare_incidents`).** Events sorted per incident; features taken from the
**first** event (what was known at opening), outcomes from the **last**. Categorical values are
anonymized codes (`Category 55`, `Group 56`). Engineered, leakage-safe features:
`open_hour`, `open_dow`, `priority_num/impact_num/urgency_num`, `group_load_24h` (incidents opened
in the same group in the preceding 24 h, strictly earlier). Per-group historical breach rate /
median resolution time are computed **from the training period only** inside the experiments.

**Targets.** `breached_sla` (= not `made_sla`, final state); `resolution_hours` (resolved_at −
opened_at; 1,556 incidents never resolved are excluded from that task); `final_assignment_group`.

**Split.** Time-based 70/15/15 by `opened_at` — train 17,442, val 3,738, test 3,738.

**Known properties (measured, relevant to every result on this data).**
* Strong base-rate drift: SLA breach rate 42.3% (train period) vs 23.1% (val) and 23.4% (test).
* Resolution time is extremely heavy-tailed: p10 0.1 h, median 22.1 h, p90 381 h, p99 2,843 h
  (all incidents); the test period's median is 3.0 h.
* Priority is 95% "3 - Moderate".
* Excluded from features as leakage: reassignment/reopen counts, update counts, resolved/closed
  timestamps, final group; for routing also the initial assignment group (the decision being
  predicted — its accuracy is reported as the human baseline instead).

## 2. Customer-support tickets (Tobi-Bueck / Softoft)

| | |
|---|---|
| Label | **PUBLIC — synthetic**: the publisher describes it as generated by a synthetic IT-ticket generator |
| Source | Hugging Face `Tobi-Bueck/customer-support-tickets`, file `aa_dataset-tickets-multi-lang-5-2-50-version.csv` |
| URL | https://huggingface.co/datasets/Tobi-Bueck/customer-support-tickets |
| Citation | doi:10.57967/hf/6184 |
| License | **CC BY-NC 4.0 — non-commercial use only** (this project is a non-commercial portfolio) |
| Raw size | 28,587 tickets (16,338 English, 12,249 German) |
| Prepared | 16,338 English tickets |
| Used for | P4.1 text classification; ticket text in the synthetic generator |

**Fields.** subject, body, answer, `queue` (10 classes), `type` (Incident / Request / Problem /
Change), `priority` (low / medium / high), tags.

**Preparation (`prepare_tickets`).** English only; `text = subject + body`; tickets with ≤10
characters dropped; exact duplicates after whitespace/case normalization removed **before**
splitting (0 found). Stratified 70/15/15 by queue, seed 42 — train 11,433, val 2,450, test 2,455.
A near-duplicate check (TF-IDF cosine of each test ticket to the train set) is reported with
every classification result.

**Queue distribution (English):** Technical Support 4,737 · Product Support 3,073 · Customer
Service 2,410 · IT Support 1,942 · Billing and Payments 1,595 · Returns and Exchanges 820 ·
Service Outages and Maintenance 664 · Sales and Pre-Sales 513 · Human Resources 348 · General
Inquiry 236.

**Caveat.** Because the texts and labels are generated, classifier scores on this data measure
how well a model recovers the generator's labelling, not accuracy on real tickets. They are
reported as a benchmark on a public synthetic dataset, never as real-world accuracy.

## 3. CQADupStack — unix subforum

| | |
|---|---|
| Label | **PUBLIC — real** (StackExchange posts, human-annotated duplicate links) |
| Source | Hoogeveen, Verspoor, Baldwin (ADCS 2015); BEIR/MTEB packaging `mteb/cqadupstack-unix` |
| URL | https://huggingface.co/datasets/mteb/cqadupstack-unix |
| License | CC BY-SA 4.0 |
| Size | corpus 47,382 posts; 1,072 queries; 1,693 duplicate judgements |
| Used for | P4.3 duplicate detection (retrieval + duplicate decision) |

**Preparation (`prepare_duplicates`).** Queries restricted to those with ≥1 judged duplicate.
Queries also exist in the corpus; as in BEIR (`ignore_identical_ids`), a post is never counted as
its own duplicate. Queries split 50/50 (seed 7) into a threshold-selection half and a test half.

## 4. Synthetic multi-organization ticket history (ours)

| | |
|---|---|
| Label | **SYNTHETIC** |
| Generator | `ml/nexadesk_ml/synthetic.py`, parameters in `Config` (saved to `data/synthetic/config.json`), seed 20260930 |
| Size | 12,000 tickets — Helix Health 5,500 · Brightline Retail 4,000 · Orbital Engineering 2,500 (all "(Synthetic)"); 480 planted duplicate pairs + 1,413 hard-negative pairs |
| Used for | load/scale testing (P10–P11), in-domain duplicate sanity check, demos |

**What is real and what is assumed.**
* Text, queue, type and priority: sampled from dataset 2's **train split** (never test texts).
  Priority `critical` = `high` Incidents in the outage queue (177 tickets).
* Resolution times: bootstrap samples from the **real** UCI distribution for the matching
  priority (train period, resolved within 60 days).
* Arrival times (180 days from 2026-03-01; business-hour and weekday seasonality),
  requesters, first-response times (log-normal around assumed medians), reopen rate (5%) and
  duplicates (4% resubmissions within 72 h, with sentence reordering/removal, a nudge prefix
  and typos): **assumptions**, listed in `Config`.
* SLA outcomes are computed against NexaDesk's default SLA policy. Because real resolution
  times are long relative to those defaults, the generated resolution-breach rates are high
  (critical 78%, high 73%, medium 53%, low 35%) — a property of this scenario, not a finding.
